# Известные ограничения

<!-- l10n: source=reference/known-limitations.md -->
> Перевод [исходной страницы на английском языке](../../../reference/known-limitations.md) для OmsiLaunch 0.1.0-beta3. Нормативной является английская страница: при расхождениях приоритет имеют английская страница и код.

На этой странице по коду перечислено всё, что в OmsiLaunch 0.1.0-beta3 имеет статус `UNAVAILABLE`, `PARTIAL` или является принятым риском, чтобы пользователи и интеграторы не опирались на поведение, которого продукт не обеспечивает. В каждой строке указаны ограничение, его стабильность, причина его существования и место, где оно описано подробно. Нормативной является английская документация; локализованные копии в `docs/localized/` не поддерживаются на том же уровне и могут отставать (см. последний раздел).

<a id="session-end-and-process-control"></a>
## Завершение сеанса и управление процессом

| Ограничение | Стабильность | Подробности |
| --- | --- | --- |
| Остановка сеанса — это принудительное завершение: `session.stop`, пункт «End session» в трее (завершить сеанс), Ctrl+C и `CloseAsync` приводят к `TerminateProcess`. Процедура завершения OMSI не выполняется, OMSI не перезаписывает `options.cfg` и свои логи при выходе, а любое несохранённое состояние OMSI теряется. Это сделано намеренно: так OMSI не может перезаписать восстановленные файлы. | так задумано | [жизненный цикл сеанса](../concepts/session-lifecycle.md) |
| Кооперативное завершение через WM_CLOSE с тайм-аутом и откатом к принудительному завершению не реализовано | `UNAVAILABLE` (решение по продукту, S-11; в раунде закрытия проверки в runtime OMSI проигнорировал `WM_CLOSE`, отправленный его главному окну) | [статус проверки в runtime](../status/runtime-validation-status.md) |
| При закрытии консоли или выходе из системы у владельца есть бюджет 4 s на остановку и восстановление; всё оставшееся восстанавливается по журналу при следующем запуске | закрытие консоли проверено в runtime; выход из системы не проверялся | [транзакции и восстановление после сбоя](../concepts/transactions-and-recovery.md) |

<a id="transaction-recovery-and-lease"></a>
## Транзакция, восстановление после сбоя и lease

| Ограничение | Стабильность | Подробности |
| --- | --- | --- |
| Аренда установки (lease) — это семафор `Local\`: один владелец на установку **в пределах сеанса входа в систему**; между пользователями не соблюдается; не освобождается, пока другой процесс удерживает дескриптор; любой процесс того же пользователя может удерживать имя | принятый риск (S-18) | [транзакции и восстановление после сбоя](../concepts/transactions-and-recovery.md) |
| Восстановление после сбоя отклоняется (`OL_E_INSTALLATION_BUSY`), пока работает процесс OMSI, записанный в журнал, а для журнала без PID — любой `Omsi.exe` из этого корневого каталога | так задумано | как выше |
| Изначально отсутствовавший путь overlay, содержимое которого изменилось во время сеанса, блокирует восстановление (`OL_E_RECOVERY_ABSENT_OWNERSHIP_MISMATCH`) до ручной проверки | так задумано | как выше |
| Журналы, созданные до появления отпечатков владения, может закрыть только сеанс с идентичными запланированными байтами (`OL_E_RECOVERY_ABSENT_OWNERSHIP_UNVERIFIED`) | `PARTIAL` | как выше |
| Восстанавливаются только пути, которыми владеет сеанс. Собственные записи OMSI во время сеанса (`options.cfg` `[last_map]`, когда ни один параметр не накладывает overlay на `options.cfg`, `Texture\standard.ipr`, кэши, `laststn.osn`, профиль водителя, логи) сохраняются, как после прямого запуска OMSI | так задумано | [транзакции и восстановление после сбоя](../concepts/transactions-and-recovery.md) |
| Удаление устаревшего `closecheck` перед сеансом является окончательным (фиксируется, но не восстанавливается), когда `SuppressStaleClosecheckWarning` равно true | так задумано | как выше |

<a id="runtime-control"></a>
## Runtime-управление

| Ограничение | Стабильность | Подробности |
| --- | --- | --- |
| `weather.set` отклоняется (`OL_E_RUNTIME_SETTING_NOT_PERSISTENT`): OMSI перезаписывает оба профилированных кандидата ветра на следующем такте погоды | `UNAVAILABLE` | [возможности](capabilities.md) |
| Запись календаря (`SetActualDateTime`) | `UNAVAILABLE` (BI-002) | `calendar.set-actual-date-time` |
| Запись строковых переменных, именованные триггеры, звуковые триггеры (владение управляемыми строками Delphi) | `UNAVAILABLE` (BI-004) | `scripts.string.read` только для чтения |
| Нет перемещения ТС, нет пространственной перепривязки между тайлами, нет безопасного для ODE права на изменение трансформации; поля позиции доступны только для чтения | `UNAVAILABLE` (BI-008) | `road-vehicle.read` |
| `camera.lock` / `camera.unlock` требуют PlayerVehicle; у headless-запуска NEW_MAP его нет (его предоставляет сохранённая ситуация) | так задумано (BI-007) | RV-004 |
| Runtime-изменения (`time.set`, `camera.set`, `camera.lock`, `vehicle.variable.set`, spawn, place-random, текстуры D3D) не записываются в журнал и не восстанавливаются | так задумано | [runtime-управление](runtime-control.md) |
| Слепое пятно отпечатка handle: объект того же класса и определения, пересозданный по тому же адресу между двумя чтениями списка, не распознаётся как устаревший; для времени жизни при естественном удалении (RV-002) нет безопасного способа воспроизвести его в runtime, оно покрыто офлайн-тестами | `PARTIAL` | [runtime-управление](runtime-control.md) |
| Результаты ограничены почтовым ящиком (mailbox) на 64 KiB: длинные списки усекаются (`truncated=true`); данные пикселей ограничены 48 KiB на один `d3d.texture.update` | так задумано | [возможности](capabilities.md) |
| Канал с одним запросом в полёте: один запрос за раз на сеанс; занятый слот даёт `OL_E_RUNTIME_CHANNEL_BUSY`; идентификаторы запросов нельзя использовать повторно | так задумано | [runtime-управление](runtime-control.md) |
| Телеметрия — это слот последнего значения: всплески чаще, чем выборка хоста раз в 100 ms, могут терять промежуточные события (порядковые номера позволяют различать одинаковые последовательные события; разорванные выборки пропускаются) | `PARTIAL` | [постоянный плагин](../concepts/permanent-plugin.md) |
| Сброс устройства D3D наблюдался в runtime (`resetting`, `restored`, инвалидация поколения); отдельный переход `lost` воспроизвести не удалось, потому что устройство OMSI сразу перешло в `DEVICENOTRESET` | `PARTIAL` (RV-007) | [статус проверки в runtime](../status/runtime-validation-status.md) |
| Результаты ограниченных списков (операции `timetable.*.list`, `vehicle.variables.list`, `vehicle.string-variables.list`) возвращают не больше строк, чем помещается в runtime-слот на 64 KiB; остальные строки не входят в ответ, при этом `truncated=true`, а `returned_count` меньше (аудит документации BUG-05). В этом выпуске постраничной выборки нет | так задумано | [возможности](capabilities.md) |
| `timetable.logs.read`, `road-vehicles.list`, `humans.list`, `vehicle.constants.list` и `vehicle.curves.list` не являются ограниченными: результат больше слота завершается ошибкой `OL_E_RUNTIME_RESPONSE_TOO_LARGE` (ни для одной из них на протестированных картах не наблюдалось) | `PARTIAL` | [возможности](capabilities.md) |
| Самостоятельно сообщаемые строки подтверждения (`PublicCapabilityRegistry` `RuntimeValidation`, `GetCapabilitiesAsync` `EvidenceState`) не были обновлены после раунда закрытия проверки в runtime: для `camera.lock` по-прежнему указано `STATICALLY_VALIDATED`, а для `runtime.d3d.lifecycle.reset` — `IMPLEMENTED_NOT_RUNTIME_VALIDATED`. Авторитетной является страница [статус проверки в runtime](../status/runtime-validation-status.md) | отставание документации, а не различие в поведении | [возможности](capabilities.md) |
| Некоторые расширенные поля графа карты/тайлов/путей/объектов не предоставляются; runtime-читатели — это типизированные снимки, заблокированные проверкой профиля, и никогда не произвольный доступ к памяти | так задумано | [возможности](capabilities.md) |
| Чтение памяти внутри процесса выполняется по схеме «проверка, затем использование» на живом OMSI; одновременное изменение в OMSI между проверкой и чтением может дать несогласованный снимок (`OL_E_RUNTIME_OPERATION_FAILED`) | принятый риск (S-33) | |

<a id="local-control-plane-and-trust-model"></a>
## Локальная плоскость управления и модель доверия

| Ограничение | Стабильность | Подробности |
| --- | --- | --- |
| Модель доверия в пределах одного пользователя: именованный канал (named pipe) (`CurrentUserOnly`), отображения памяти handoff/телеметрии/runtime и семафор lease доступны любому процессу того же пользователя Windows. Такой процесс, прочитав `session_id`, может читать состояние, останавливать сеанс или выполнять runtime-операции. | принятый риск (S-06, S-30) | [локальное управление](local-control.md) |
| Конечная точка управления существует только пока владелец находится в состоянии `Running`; во время запуска и после завершения сеанса клиент получает `OL_E_NO_ACTIVE_SESSION` (выход 4) | так задумано | [локальное управление](local-control.md) |
| Если имя pipe уже занято другим процессом, владелец продолжает работу без конечной точки (`ListenFault`), а второй запуск может ошибочно сообщить `OL_E_SESSION_ALREADY_ACTIVE` | принятый риск | [локальное управление](local-control.md) |
| `.omsilaunch\` наследует ACL корневого каталога OMSI; явное управление доступом не применяется | принятый риск (S-31) | [транзакции и восстановление после сбоя](../concepts/transactions-and-recovery.md) |

<a id="documentation"></a>
## Документация

Нормативной документацией этого выпуска являются английские страницы в `docs/`. `docs/localized/<locale>/` содержит переводы тех же страниц `0.1.0-beta3` (см. [`LOCALIZATION-MANIFEST.md`](../../LOCALIZATION-MANIFEST.md)); если перевод расходится с английским текстом, авторитетными являются английский текст и код. Перечисленные там исторические и устаревшие (legacy) страницы доступны только на английском.

См. также: [возможности](capabilities.md), [статус проверки в runtime](../status/runtime-validation-status.md), [ошибки](errors.md).
